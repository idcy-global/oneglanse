title: Self-Hosted Setup
description: Deploy the always-on OneGlanse app on an Ubuntu VPS.
---

Self-host mode runs Web, Agent, Postgres, ClickHouse, and Redis through Docker. It supports manual prompt runs and recurring schedules. Provider sign-in happens on a desktop machine; you then upload the sessions to the Agent on the VPS.

## Requirements

- An Ubuntu 22.04 or 24.04 VPS and a domain whose DNS A record points to it
- A non-root user with `sudo` access
- An OpenAI or Anthropic API key, or an OpenAI-compatible endpoint and its API key
- Provider accounts and a desktop machine for browser sign-in
- A ThorData residential proxy API endpoint for provider browser traffic in self-host mode

Datacenter IPs are often challenged by provider interfaces. The current self-host browser path uses ThorData proxy discovery and requires `THORDATA_PROXY_API_URL`. See [Environment Variables](/environment-variables) for that setting.

## Recommended automated setup

On the VPS, connect as a non-root sudo user. The script rejects root. Set the DNS A record before starting so certificate issuance can succeed.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/idcy-global/oneglanse/main/scripts/setup-vps.sh)
```

The interactive script asks for a domain, install directory, analysis key, proxy API URL, and upload token. It installs missing Docker, Node.js, Git, and nginx dependencies, configures `.env`, starts the Docker stack, configures nginx and attempts a Let's Encrypt certificate, and opens firewall ports if `ufw` is installed. It generates an upload token when you leave that prompt blank. It also handles first-run Docker group access for its setup session.

The script keeps the session upload endpoint on host loopback and does not open TCP 3333 in the firewall. It can continue if certificate issuance fails; confirm HTTPS works before using the public app. Run it with `bash <(...)` so its prompts can read your terminal. On a fresh install it replaces weak example database and application secrets with random values. The `.env` file is restricted to owner-only access. When any existing PostgreSQL, ClickHouse, or Redis data volume is detected, the installer preserves current credentials rather than rotating passwords underneath existing data; if the original `.env` is missing, setup stops and asks you to restore it.

You can also clone the repository and run the script from that checkout:

```bash
git clone https://github.com/idcy-global/oneglanse.git /tmp/oneglanse
bash /tmp/oneglanse/scripts/setup-vps.sh
```

After either setup path, continue at [Capture and upload provider sessions](#capture-and-upload-provider-sessions).

## Manual setup

### 1. Prepare the VPS and DNS

Use a non-root sudo user. Point your app hostname, such as `app.example.com`, to the VPS IP before requesting a certificate.

Install Docker, Node.js 20 or newer, Git, nginx, and Certbot. For example, on Ubuntu:

```bash
sudo apt-get update
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker "$USER"
newgrp docker
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs git nginx certbot python3-certbot-nginx
```

### 2. Clone and configure

```bash
git clone https://github.com/idcy-global/oneglanse.git "$HOME/oneglanse"
cd "$HOME/oneglanse"
cp .env.example .env
```

Edit `.env`. Set your public URL, one analysis provider, the ThorData API endpoint, and an upload token:

```dotenv
APP_URL=https://app.example.com
API_BASE_URL=https://app.example.com
ONEGLANSE_APP_MODE=self-host
OPENAI_API_KEY=your-key
THORDATA_PROXY_API_URL=https://your-thordata-api-link
AGENT_AUTH_UPLOAD_TOKEN=your-long-random-secret
```

For Anthropic, set `ANTHROPIC_API_KEY` and `ANALYSIS_LLM_PROVIDER=claude` instead of `OPENAI_API_KEY`. Keep `ONEGLANSE_APP_MODE=self-host`: the automated setup script sets it, but manual setup must set it in `.env`. The bootstrap command generates `BETTER_AUTH_SECRET` and `INTERNAL_CRON_SECRET` if they are blank or still placeholders. See [Environment Variables](/environment-variables) for all supported values.

### 3. Start the stack

```bash
node scripts/run-compose.mjs bootstrap
```

This builds the commercial application images from the checked-out IDCY source. Redis and ClickHouse base images are fetched separately. Allow sufficient build resources on first installation. The Web app listens on `127.0.0.1:3000`; Postgres, ClickHouse, and Redis also bind to loopback. The Agent upload API binds to host `127.0.0.1:3333` and is not publicly exposed.

Check the containers:

```bash
docker ps
```

Look for `oneglanse-web`, `oneglanse-agent-worker`, `postgres_db`, `clickhouse_db`, and `redis`.

### 4. Configure nginx and HTTPS

Create `/etc/nginx/sites-available/oneglanse` with your real hostname:

```nginx
server {
    listen 80;
    server_name app.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/oneglanse /etc/nginx/sites-enabled/oneglanse
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d app.example.com
```

Verify `https://app.example.com` loads before creating an account.

## Capture and upload provider sessions

On your desktop machine, clone the IDCY repository and install dependencies if you have not already. Provider sessions are credentials: first create a private SSH tunnel from your desktop to the VPS (replace the SSH user and address):

```bash
ssh -N -L 3333:127.0.0.1:3333 VPS_USER@VPS_HOST
```

In the desktop checkout's `.env`, use the tunnel and the upload token from the VPS. Keep the SSH tunnel open while uploading:

```dotenv
AGENT_AUTH_UPLOAD_URL=http://127.0.0.1:3333/auth/sessions
AGENT_AUTH_UPLOAD_TOKEN=your-long-random-secret
```

The HTTP transfer travels through the encrypted SSH connection, not public cleartext. Do not use the `ONEGLANSE_VPS_IP` direct HTTP shortcut across the public internet.

Run `pnpm auth` to prepare the Camoufox browser runtime, build the required workspace packages, and open the local provider sign-in UI on port 3100. The full local app stack and its database services are not required.

```bash
pnpm auth
```

Finish sign-in in the browser, return to the terminal, and press Enter. If sessions changed and upload is configured, the command asks whether to upload them. To send existing sessions later without signing in again:

```bash
pnpm upload:vps
```

A separately secured HTTPS reverse-proxy endpoint is also possible; the Agent does not provide HTTPS by itself. Do not publicly expose port 3333.

Open the Providers page on the VPS app to check connection status. Then add prompts and run them. Configure recurring runs on the Schedule page.

## Updating

From the VPS checkout:

```bash
cd "$HOME/oneglanse"
git pull
node scripts/run-compose.mjs bootstrap
```

Bootstrap rebuilds the commercial app images from the checked-out source and recreates containers. Expect a brief interruption during recreation. If you changed `.env`, this command also applies the new values.

## Session-upload security

The Agent exposes `POST /auth/sessions` on host loopback port 3333 and requires `AGENT_AUTH_UPLOAD_TOKEN`. Use the SSH tunnel above or a separately secured HTTPS endpoint. Never send provider sessions or upload tokens directly over public HTTP.

For an older VPS installation, remove any public 3333 firewall allowance **after confirming SSH access**:

```bash
sudo ufw delete allow 3333/tcp
```

Check that `docker ps` shows `127.0.0.1:3333` rather than `0.0.0.0:3333` or `[::]:3333`. Do not proxy the upload endpoint through the normal unauthenticated public Web proxy.
Do not expose the database ports. In the Compose file, they bind to loopback. See the repository [security policy](https://github.com/oneglanse/oneglanse/blob/main/SECURITY.md) for the full data-flow boundary.

For deployment problems, see [Troubleshooting](/troubleshooting).
